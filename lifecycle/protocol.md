# Fresh-agent tournament protocol
Frozen before wave one. Model gpt-6.2-sol, medium reasoning, priority service tier. Persona retention seat independently randomized and committed; each wave one prior alias and one new alias; both runtimes fresh. Alias interaction exploratory.

## Primary comparison
The unit is one paired wave. The two participants in each wave receive the same new task and rules; the only prompted treatment difference is a short method note from a completed prior contestant versus a length-comparable neutral note. Treatment seat is determined by a committed, counterbalanced schedule; both seats on the same platform/model/effort and spawn with no inherited conversation. No live opponent interaction or cross-seat file reads. One valid final answer per seat, frozen on completion; no repair prompts, reruns or simulated contestants. The frozen challenge disallows tools equally for both fresh seats.

## Lifecycle
Waves launch strictly sequentially. Spawn the two unique native-agent paths with `fork_turns=none`; no other fresh contestants may launch until both prior participants are completed or explicitly timed out/closed. The concurrent limit concerns active contestants, not organizers, capture workers or the platform. Record the path, kickoff (observed, UTC), finish receipt (observed, not authoritative compute time), full invite, raw response and full scored result for each. Report missing, partial, invalid and timed out attempts without quietly replacing them. No claim that immutable platform/audit history was deleted. Exposing only the specific prior note is scoped handoff, not a wipe. Agent wall-clock latency includes platform scheduling; no tokens/price unless instrumented and available.

## Carryover
Use a general method observation from the previous wave's designated source seat (not selected by correctness, score or ranking). The note must contain no digits or suggested action/answer on a prior/current instance, solution dumps, source code, score or grader information. Take it verbatim if valid, else use most recent valid prior observation and log its origin. For wave 1, use method text from a separately completed native agent's same-family strategy if available and label this initial source. Future agents cannot see the archive, other agent outputs, or the seed/instance generator/grader. Observers may grade after responses freeze; no responder sees grader output.

## Reporting
Preserve all submitted rows. Primary correctness over paired observable submissions; tabulate both-correct, handoff-only, control-only, neither and incomplete waves. Describe observable losses/latency separately. If the run cannot complete all 50 waves, report actual agent paths and waves, not intended sizes. Method notes are content-bearing but not uniform interventions; family-specific strategy, repeated observation lineage, platform latency and fixed challenge sample constrain causal claims.

## Replaying the collection
`node invite.cjs N` prints the exact paired invitations; `--record` commits this snapshot once and marks the observed preparation time. The organizer submits those invitations using fresh native agents; the script does not spawn anyone. After the native spawn succeeds, append its observed admission(s) with `node admit.cjs waveNN[a|b] …`. Both final completions must be observed before preparing the next invitation. After each native final-answer event, `node record.cjs waveNN[a|b] completed '<verbatim final>'` appends the final response, public scoring status and card self-report. Timeout interventions, if necessary, are explicit and do not count as answers. `node render.cjs` checks the observed sequence and rebuilds one JSON profile per record, a JSONL roster, and an HTML roster.

Admission time after the two launch calls is a coarse observation, not compute timing. Individual preparation/record time is stamped by the collection script. Waves one and two predate the optional admission checkpoint log but exact invitation and both observed final responses remain.
